# 脑暴：先摆决策表，再选

## 概述

**核心原则：The first idea is a candidate, not the answer.**（第一个想法是候选，不是答案。）
**Violating the letter of this rule is violating the spirit of this rule.**

## 铁律

```
NO DECISION WITHOUT A DECISION TABLE
NO PLAN BEFORE THE TABLE IS SETTLED
```

## 决策表（固定形状）

| 列 | 放什么 |
| --- | --- |
| **问题** | 要决定的那一件事，一句话 |
| **候选** | ≥2 个真实可走的方案（非平凡问题 ≥3）；每个一句代价 |
| **当前倾向** | 你推荐哪个 + 为什么 —— **这不是批准** |
| **未决问题** | 只有用户能定的那几个 |

规则：

- 表没摆出来，不许写计划、不许写实现。
- **「当前倾向」是倾向，不是决定**：用户没点头之前，它在语义上是 NOT approved。
- 未决问题拿去问用户；推荐不能代替用户拍板。用户拍完 → 把小节改成「已裁决」，逐条写下他选了什么。
- 能自己定的别烦用户（写进倾向里、注明理由）；只有用户能定的才进未决。
- 候选少于 2 个 = 还没想开；候选没写代价 = 没想。

## 流程

1. 把问题写成一行（"要决定什么"，不是"要做什么"）。
2. 列候选 —— **"不做"是一个候选**，只要它真实存在。
3. 逐候选写代价与适用条件（什么时候选它）。
4. 写当前倾向 + 理由。
5. 未决问题问用户；自己能定的定掉。
6. 表定稿 → 转 `smart-design` 定形状（再转 `smart-plan` 拆任务）；这条取舍要长期留档 → `smart-adr`。

## Red Flags —— 停下

- 直接说"我打算这么做"，没有表
- 候选全是稻草人（只有一个真方案，其余是用来垫的）
- 把「当前倾向」写成了"决定"
- 未决问题被自己悄悄拍板
- 问题一行写不出来（那说明还没搞清要决定什么）

## Rationalization Prevention

| 借口 | 现实 |
| --- | --- |
| "问题很简单，不用表" | 简单问题的表三行就写完；跳过表通常是因为没想 |
| "先写起来，边写边定" | 那是把决定埋进代码，事后没人看得见 |
| "推荐就是决定" | 倾向不是批准。用户没点头就还是未决 |
| "问用户太烦" | 你替他拍板，错了代价是他的。分清"我能定"和"只有他能定" |
| "我想清楚了，表是形式" | 表是给你自己看的：三周后没人记得"当时为什么没选 B" |
