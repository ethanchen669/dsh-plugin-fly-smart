# 卡住、调试与进阶

摘自 `smart-tdd`。卡住时的顺序：先怀疑测试，再怀疑实现。

## 卡住时

| 问题 | 解法 |
|------|------|
| 不知道怎么测 | 写出想要的 API。先写断言。问用户。 |
| 测试太复杂 | 设计太复杂。简化接口。 |
| 必须 mock 一切 | 代码耦合太紧。用依赖注入。 |
| 测试准备代码巨大 | 抽 helper。还是复杂？简化设计。 |

## 调试

发现 bug？先写一个复现它的失败测试，走完 TDD 循环。这个测试既证明修复有效，也防止回归。

**Never fix bugs without a test.**
